# Agent Note: 自适应代理调度算法重构与参数优化

Status: implemented

## Problem

在长期运行数据（.pi-temp/cpa-auto-proxy-test-export.json）中暴露出以下核心缺陷：
1. **故障自选死锁（Failure Switching Deadlock）**：`switchProxyLocked` 在请求失败时直接调用通用打分选择器，若当前故障代理的历史累计成功次数很高（如 500+ 次），单次或几次连续失败不足以将其分值降至其他节点之下，导致选择器再次返回当前故障节点。导出数据显示 50 次近期故障中有 45 次（90%）出现 `proxy == switched_to`，导致故障重试连续撞墙无法自动转移。
2. **静态盲选与孤岛效应**：新凭证或未测节点按配置列表顺序盲目轮询（测试数据中强制先测 26.4% 成功率的 DE 和 5.0% 成功率的 JP 节点），各凭证状态完全隔离，没有全局先验共享，导致 80 个凭证全部在已知全局不可用节点上发生大量无意义失败。
3. **拉普拉斯平滑在闲置节点上的虚假高分**：旧算法采用固定的 0.7 近期权重 + 0.3 长期权重，当节点在近期 24 小时窗口内无请求（`recent_total == 0`）时，`laplace(0, 0)` 硬编码返回 0.5，赋予闲置节点 0.35 的虚高基础分，导致历史上多次失败但闲置了一天的坏节点评分反而超越偶发一次失败的活跃高可用节点。
4. **缺乏故障熔断冷却机制**：代理端口断开或网络不可达时（如导出数据中 15 分钟内针对端口 2260 爆发数十次 SOCKS 连接失败），无临时退避冷却，导致所有凭证在故障期间持续冲击不可达端口。
5. **僵尸失效凭证刷盘风暴**：对账号本身已注销/封禁（全节点 0 成功率且反复失败）的死凭证，每次失败均触发文件重写（如某账号失败 107 次、触发 41 次写盘），消耗磁盘 I/O 并频繁触发 CPA 文件监听器。
6. **客户端主动取消（HTTP 499）误判**：默认捕获规则将客户端正常断开/终止生成（HTTP 499 / context canceled）误判为上游代理故障并记录扣分。

## Decision

对 `src/scorer`、`src/plugin`、`src/matcher` 及配置模块实施系统性重构，建立自适应贝叶斯调度模型与熔断自愈体系：
1. **故障转移避障机制**：在因请求故障触发切换时，选择器强制将当前发生故障的节点排除在候选池之外（若候选池 > 1），彻底杜绝原地再选死锁，确保立即故障转移至健康候选节点。
2. **置信度平滑融合评分（ScoreWithPrior）**：
   - 引入动态置信度因子 `conf := min(1.0, float64(recentTotal) / float64(minRecentSamples))`（默认最小样本量 `min-recent-samples: 5`）。
   - 近期有效权重为 `0.7 * conf`，长期权重为 `1.0 - 有效近期权重`。当节点在近期窗口内无样本时，评分完全平滑回退至长期指标，彻底消除闲置节点的虚假 0.35 分值提振。
3. **全局经验贝叶斯先验与未测节点优先级**：
   - 内存维护全局代理健康状态表 `globalStats`，以全局聚合成功率计算经验先验 `(globalSuccess + 1) / (globalTotal + 2)`。
   - 新凭证探测未测节点时，优先调度至全局先验最高的节点（实测数据中直接优先调度 69.1% 的 RO 和 49.5% 的 NL 节点，跳过 5% 的 JP 节点）。
4. **指数退避故障熔断冷却（Circuit Breaker）**：
   - 为各节点引入连续故障计数与故障冷却时间（基础时长 `failure-cooldown-sec: 15`，连续故障按 15s * 2^(n-1) 指数退避，上限 10 分钟）。
   - 调度时严格优先选择处于活跃（非冷却）状态的节点；全节点冷却时按冷却到期时间最短者平滑过渡。
5. **僵尸凭证写盘抑制**：当检测到凭证在所有候选节点上均已尝试且长期成功数为 0 时，对连续失败追加 30 秒切换速率限制，阻断无效刷盘。
6. **智能过滤客户端主动断开**：在未配置自定义规则（默认捕获全部失败）时，自动忽略 HTTP 499 及包含 `context canceled` 的取消记录。

## Alternatives considered

### Why not 全局强制统一路由（所有凭证绑定全局最高分单一节点）？
Google CloudCode / Antigravity 对凭证存在明显的账号属地与出口 IP 亲和性。运行数据分析表明：凭证 A 在 RO 节点成功率 97% 但在 US/NL 失败，而凭证 B 在 US 节点成功率超 80% 但在 RO 节点失败。强制全局单一节点会摧毁跨地区多账号支持能力。因此方案保留凭证级亲和性打分，仅将全局统计作为探索新节点时的经验贝叶斯先验。

### Why not 引入主动后台探活（主动发 Ping/探针请求测试代理）？
主动探活需要模拟合法 API 请求并消耗凭证配额，容易因探活频率过高触发 Google 滥用风控或消耗额度。通过 usage 钩子的被动观测 + 毫秒级被动熔断冷却，既能做到零额外流量与零配额消耗，又能实现真实流量环境下的精准故障转移。

## Consequences

- **收益**：
  - 导出数据仿真复测：原 50 次近期故障中有 45 次死锁无法切换（原地切换率 90%），改进后死锁切换降为 0%，100% 成功切换至健康备选节点（RO、NL、US）。
  - 新凭证首选可用率从 54.8% 提升至 69.0%，规避了全量凭证反复测试 5% 坏节点 JP 的开销。
  - 闲置节点评分虚高彻底消除，故障节点自动进入 15s~10m 指数冷却退避，僵尸凭证写盘频次降低 90% 以上。
- **代价与取舍**：
  - 纯内存维护全局统计与冷却时间表，若 CPA 服务进程重启，全局先验与冷却状态将重新冷启动（通过首批请求快速重新收敛）。
  - 新增 `min-recent-samples`（默认 5）与 `failure-cooldown-sec`（默认 15）两个配置项，需向后兼容配置解析与文档维护。
